flAWS.cloud Walkthrough
AWS S3 MISCONFIG LEAKED CREDENTIALS EC2 SNAPSHOTS SSRF · IMDS IAM ENUMERATION LAMBDA · API GATEWAY

A full six-level walkthrough of the flAWS.cloud challenge — an authorized, deliberately vulnerable AWS environment. The attack chain runs from an anonymous public S3 bucket, through credentials leaked in git history and a publicly shared EC2 snapshot, to an SSRF that steals instance-role credentials from the metadata service, and finally IAM privilege enumeration that pivots into a Lambda behind API Gateway. Every finding includes real AWS CLI evidence, root cause, and remediation. All credentials and account identifiers are redacted.

THE ATTACK CHAIN
Level 1 — S3 Public Access
Anonymous Bucket Listing
The target site is itself an S3 bucket. aws s3 ls --no-sign-request enumerated it anonymously, exposing an unlinked secret-*.html file — defeating security-through-obscurity and leaking the next level.
✓ Exploited
Level 2 — IAM Group Misconfig
"Any Authenticated AWS User"
Anonymous access was fixed, but the bucket granted the Authenticated Users group — i.e. any AWS account. A brand-new zero-privilege user listed it: anonymous → AccessDenied, signed → success.
✓ Exploited
Level 3 — Secrets in Git
Credentials in Public .git History
A public .git directory was recovered with aws s3 sync. Walking its history surfaced an access key "deleted" in a later commit but preserved forever — a cross-account compromise that then enumerated the whole account.
✓ Exploited
Level 4 — EC2 / EBS
Publicly Shared Snapshot
An EBS snapshot with createVolumePermission open to all accounts was discovered via describe-snapshots. Documented the clone → attach → mount path to read the server's provisioning secrets.
◼ Recon done · runbook
Level 5 — SSRF → Metadata
Stealing Instance-Role Credentials
An open proxy was coerced into fetching 169.254.169.254 (IMDSv1), handing over the instance role's temporary credentials (ASIA… + session token) — the classic SSRF-to-IMDS cloud breach pattern.
✓ Exploited
Level 6 — IAM → Serverless
Privilege Enumeration & Lambda Pivot
An over-permissioned user (SecurityAudit + apigateway:GET) enumerated its own policies, discovered a Lambda and its API Gateway trigger via lambda get-policy, and invoked the endpoint to finish the challenge.
✓ Exploited
